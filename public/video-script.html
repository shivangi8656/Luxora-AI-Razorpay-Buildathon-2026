Section B: Live Failure Scenarios & Deterministic Graceful Recovery
FAILURE SCENARIO 1: PAYMENT GATEWAY DECLINE / INSUFFICIENT BALANCE Live Test Trigger
How to Trigger:
In the Razorpay test payment modal, enter a card number ending in "0002" (e.g. 4111 1111 1111 0002) and click Pay.
System Reaction:
The gateway intercepts the card and simulates: "INSUFFICIENT_BALANCE: Your bank reported insufficient funds for this card." with structured code BAD_REQUEST_PAYMENT_ACCOUNT_INSUFFICIENT_BALANCE.
Graceful Recovery:
1. 100% Bag Preservation: The shopping bag is NEVER cleared. Items, quantities, and applied privileges remain fully intact.
2. Zero Phantom Debits: Explicit confirmation displayed that no funds were deducted.
3. Alternative Options: Immediate split-payment recommendation, 1-click UPI QR retry, or alternative card switch.
Audit Log Proof:
Firestore logs event [FAILURE] Razorpay Test Card Declined (Ending in 0002) with full error payload.
FAILURE SCENARIO 2: EXPIRED PRIVILEGE / DEACTIVATED PROMOTIONAL CODE Live Test Trigger
How to Trigger:
In the Bag Drawer promo code field, enter an expired campaign code like "EXPIRED20" or "SUMMER2025".
System Reaction:
Instead of failing with a hostile error screen or wiping the bag, the AI Concierge recognizes customer intent.
Graceful Recovery:
Displays: "Graceful Recovery: 'EXPIRED20' has expired, but LUXORA AI Concierge has auto-applied active privilege 'VIPATELIER10' (10% off) for you!" Cart values recalculate dynamically without blocking checkout.
Audit Log Proof:
Logged in customer activity session with automatic fallback application details.
FAILURE SCENARIO 3: BOUNDED GUARDRAIL MARGIN BREACH Safety Policy Trigger
How to Trigger:
AI Copilot is asked to launch an aggressive promotion exceeding 50% discount or an AI buyer attempts to purchase over the ₹50,000 spend cap.
System Reaction:
Guardrail engine triggers HTTP 422 BOUNDED_LIMIT_EXCEEDED to protect merchant gross margins.
Graceful Recovery:
The action is automatically held. AI provides a margin risk breakdown and routes the proposal to the Merchant Director for manual authorization.
Audit Log Proof:
Event [GUARDRAIL] Merchant Guardrail Breach Held recorded in Firestore audit ledger.

Section D: Defensive Q&A for Judges & Examiners
Q: How does LUXORA ensure the AI doesn't offer 90% discounts and bankrupt the merchant?
Through our Bounded Guardrail Policy. All AI proposals are clamped to a maximum 15-30% discount ceiling and checked against gross margins. Furthermore, every promotion is Gated by mandatory merchant signoff ("Deploy to Storefront") before reaching the live storefront marquee.
Q: What happens when a customer's card fails or payment gateway timeouts?
We implement Deterministic Failure Recovery: Shopping cart state is never wiped, zero ghost debits occur, the exact decline code is logged in the Audit Trail, and the user is offered 1-click retry alternatives including Split-Payment and UPI QR codes.
Q: How is an AI-buyer transaction authenticated without human button clicks?
Through our Agent Buyer Terminal protocol. The AI agent submits an acquisition request verified against active Firestore inventory, checks that the amount does not exceed the ₹50,000 spend cap, and mints an immutable SHA-256 token linked to the client's verified account.
Q: Where is data stored and how is the audit trail secured?
Data is persisted in Firebase Cloud Firestore across collections: products, campaigns, orders, and audit_logs. The audit logs contain client timestamps, IP/user tokens, action payloads, and state hashes that cannot be modified post-creation.
